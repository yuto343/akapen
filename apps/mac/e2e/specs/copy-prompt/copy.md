# プロンプトをコピーする

## 概要

確定した注釈を、定型文と「画像のパス → コメント」の並びの文章にして、クリップボードに入れる。コピーしたあともアプリは終了せず、次にホットキーを押すと、注釈が空の新しい回が始まる

## 前提

セットアップ済み、画面収録の許可あり、言語は英語（既定）、定型文はどの言語も書き換えていない状態で起動している。撮影対象のアプリ（Sample App）が出ている。確定済みの注釈が 2 件あり（コメントはそれぞれ別の文。1 件目は改行を含まない 1 行の文）、どちらの画像も置き場にある。ボタン類が出ている（枠を描く状態。準正常系だけは、確定済みの注釈が 0 件で、ボタン類が出ている）。テスト用のクリップボードには、前もって別の文章を入れておく

## 目的

画面に付けた注釈をまとめて、ターミナルやデスクトップの AI エージェントに 1 回の貼り付けで渡す。渡したあと、続けて別の依頼の注釈を付け始める

## シナリオ

### 正常系

#### コピーすると、定型文と「パス → コメント」が確定した順にクリップボードに入る

期待される結果:

- クリップボードに入った文章で、冒頭が英語の既定の定型文になっており、そのあとに空行を挟んで、1 件目の画像のパス・改行・1 件目のコメント、空行、2 件目の画像のパス・改行・2 件目のコメント、の順に並んでいる
- クリップボードに入った文章で、各パスが、画像の置き場のこの回のフォルダにある画像の絶対パスになっている

してはいけないこと:

- 通し番号や、枠の座標が入る
- 末尾に余分な改行や空行が付く
- 注釈の順番が入れ替わる
- パスとコメントの組がずれる（1 件目のパスに 2 件目のコメントが付くなど）
- 前もってクリップボードにあった文章が残る、または混ざる

#### コピーすると注釈が空になり、ボタン類が消える

期待される結果:

- ボタン類が消え、コピーしたことが分かる表示が出る
- アプリの状態で、コピーを終えた状態になっており、注釈は 0 件、直前にコピーした件数は 2、ボタン類は出ていない

してはいけないこと:

- クリップボードには入ったのに注釈が残り、次の回に前の注釈が混ざる
- ボタン類が出たまま残る

#### コピーしても、画像ファイルは消えずに残る

期待される結果:

- 保存された画像で、クリップボードに入った文章の各パスに画像ファイルがあり、赤枠の入った画像として開ける

してはいけないこと:

- 注釈と一緒に画像ファイルまで消え、AI エージェントがパスを開けない

#### コピーのあとにホットキーを押すと、注釈が 0 件の新しい回が始まる

期待される結果:

- ボタン類が出て、マウスが枠を描く操作になる
- アプリの状態で、枠を描く状態になっており、注釈は 0 件

してはいけないこと:

- 前の回の注釈が残っている
- コピーしたことの表示が消えるまで、ホットキーが効かない
- 新しい回を始めたあと、コピーしたことの表示が消えるのに合わせて、何も出ていない状態に戻ってしまう

#### 新しい回でコピーすると、前の回の注釈は入らず、前の回の画像は残っている

期待される結果:

- クリップボードに入った文章で、新しい回で確定した注釈のパスとコメントだけが並んでいる
- 保存された画像で、前の回でコピーした文章の各パスに、前の回の画像がそのまま残っている

してはいけないこと:

- 前の回の注釈のパスやコメントが混ざる
- 前の回の画像が、新しい回の画像で上書きされる、または消える

### 準正常系

#### 注釈が 0 件のときは、コピーされない

期待される結果:

- クリップボードに入った文章で、前もって入れておいた文章から変わっていない
- アプリの状態で、枠を描く状態のままで、直前にコピーした件数も変わらない

してはいけないこと:

- 定型文だけの文章がクリップボードに入る
- ボタン類が消え、コピーを終えた状態になる
